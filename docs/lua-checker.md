# Каноническая проверка Lua

Владельцы Core и расширений используют `tools/check-lua.ts` из закреплённого checkout
Performance. Копии движка проверки и самостоятельные установщики не требуются.

```sh
deno run --no-config --no-lock -A /absolute/performance/tools/check-lua.ts \
  --root /absolute/owner \
  --scope _extensions/example \
  --exclude _extensions/example/vendor \
  --library /absolute/performance/bridge \
  --server /absolute/luals/bin/lua-language-server
```

`--root` обозначает существующий абсолютный корень репозитория. Для чужого корня необходим
явный конечный список `--scope`; параметр повторяется для каждого собственного каталога или
Lua-файла. Без параметров проверяется собственный состав Performance: `bridge` и
`src/agents/lua`. `--exclude` повторяется для явно импортированных или библиотечных путей;
относительные пути не допускают выхода через `..`. Невыбранные соседние каталоги исключаются до
обхода, символьная ссылка внутри выбранного состава требует явного решения владельца.
Пустой состав отклоняется.

`--library` добавляет явно выбранные абсолютные каталоги контрактных типов. Библиотека не
становится проверенным собственным исходником. Реальные `lua-types` и `lua-plugin` выбранного
Quarto подключаются всегда; исполняемый файл Quarto выбирается через `QUARTO` либо `PATH`.
`--server` выбирает конкретный LuaLS; по умолчанию используется `lua-language-server` из `PATH`.

Используется LuaLS 3.19.2, Lua 5.4, группы `type-check` и `strong`, проверка формы таблиц и строгие
проверки nil/union. `no-unknown` включён явно. Полный JSON диагностик выводится до удаления
временной конфигурации. Проверяемые исходники не изменяются.

```sh
deno run --no-config --no-lock -A /absolute/performance/tools/check-lua.ts \
  --server /absolute/luals/bin/lua-language-server --probe
```

Контроль создаёт три ошибочных файла: выбранный `own/unknown.lua`, исключённый
`own/vendor/unknown.lua` и невыбранный `outside/unknown.lua`. Успех контроля требует настоящей
диагностики `no-unknown` только у выбранного файла. Так проверяется работа движка, собственного
состава и исключений. Контроль не заменяет проверку исходников владельца.

В CI используется единая подготовка закреплённого официального архива:

```sh
bash /absolute/performance/tools/setup-lua-ci.sh /absolute/new-luals
```

Назначение должно быть абсолютным новым путём, включая отсутствие висячей символьной ссылки.
Скрипт проверяет SHA-256 архива и версию распакованного бинарника, затем переносит подготовленный
каталог. Системные каталоги и глобальные настройки не меняются. После подготовки CI выполняет
контроль `--probe` и полную проверку с тем же `--server`.
