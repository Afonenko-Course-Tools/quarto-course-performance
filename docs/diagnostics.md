# Диагностика рендера

Начните с `quarto-course-perf render` в том же каталоге и с теми же параметрами, что и обычный
`quarto render`. Команда измеряет один нативный запуск; профили, рабочий каталог, функциональное
окружение, ввод и вывод сохраняют своё назначение. Имя Java и профили `student`/`full` не являются
условиями работы.

## Команда и место результата

```sh
quarto-course-perf render --profile student
quarto-course-perf render --perf-mode summary tasks --profile student
quarto-course-perf render --perf-mode cpu slides/index.qmd --profile student --to revealjs
quarto-course-perf render --perf-mode cpu --perf-output ../measurements index.qmd
```

Пути и профили в примерах замените существующими целями своего проекта. `--perf-mode` принимает
`off`, `summary` или `cpu`; `--perf-output` задаёт родительский каталог новых запусков. Допустимы
формы с отдельным значением и с `=`, например `--perf-mode=summary`. Оба параметра должны стоять
перед первым аргументом Quarto. Один разделитель `--` завершает префикс Performance; последующие
аргументы, включая нативный разделитель, передаются Quarto.

Выбор проекта учитывает цель рендера, самостоятельные вложенные проекты и обычные подпапки. По
умолчанию отчёт находится в `.quarto/course-perf/runs/<run-id>` выбранного проекта. Явный
относительный `--perf-output` отсчитывается от рабочего каталога команды. Итоговый путь всегда
печатается после сохранения; `render --help` передаёт справку Quarto без подготовки отчёта.

Каталог измерений должен быть отделён от `output-dir` и публикуемых `project.resources`. Пересечение
отклоняется до запуска. Стандартная `.quarto` является служебной областью Quarto. Пользовательский
`.gitignore` сохраняет свои байты.

Данные текущего запуска сначала собираются во внешнем временном каталоге, затем переносятся в
итоговый. Это позволяет закончить отчёт после штатной очистки scratch самим Quarto. Ранее
сохранённые запуски внутри `.quarto` при такой очистке могут исчезнуть. Для архива выбирайте внешний
каталог; восстановление остальных удалённых данных Quarto не выполняется. Если сохранить итог не
удалось, сообщение указывает оставшийся временный каталог.

## Что означают режимы

В `off` доступны внешние wall-время, CPU user/system и пиковая память. Внутренние агенты и
трассировка отключены; ручные фасады возвращают исходные функции. Нулевые накладные расходы из этого
не следуют: для их оценки нужен [парный эксперимент](experiments.md).

`summary` собирает доступную ручную разметку установленных расширений. Реестр содержит 230 операций
десяти пакетов, принадлежащих восьми репозиториям. Он описывает возможные точки наблюдения, а
конкретное выполнение подтверждают события, сводки и `expectations.json`. Курс без такой разметки
может успешно собраться и оставить пустую сводку операций.

`cpu` добавляет реальные V8 CPU-профили процессов Deno. Их пути приведены в `report.md`, а
инструкция открытия — в [руководстве Perfetto и Speedscope](visualization.md). CPU sampling
показывает выборки стеков; точные числа вызовов берутся из соответствующих счётчиков. Lua sampling
backend отсутствует. Выборочная трассировка функций доступна только через
[изолированный `experiment run --mode trace`](experiments.md).

Простой `render` подключает Deno preload и Pandoc init через публичные интерфейсы выбранного
runtime. Он не изменяет установленные пакеты, пользовательские TS/Lua или системный Quarto и не
патчит `run_emulated_filter`. Поэтому внутренняя операция `quarto.filter.run` в этом пути отмечена
как недоступная. Расширенный эксперимент может применять отдельный адаптер к собственной копии
Quarto; это другая граница диагностики.

## Пакеты и границы наблюдения

В `summary`, `cpu` и диагностическом эксперименте `coverage.json.packageCoverage` отделяет инвентарь
пакетов от наблюдений. `scope: "selected-project-tree"` означает дерево выбранного нативного
проекта, включая вложенные физические `_extensions`, с исключением служебных каталогов, рабочей
области диагностики и известного выходного каталога. Родитель и соседние проекты в этот инвентарь не
входят. Само наличие вложенного проекта в дереве не доказывает его исполнения.

`packages` перечисляет физические копии с относительным `path`: `installed: true` означает найденный
каталог пакета с обычным `_extension.yml`, а не активацию фильтра. Статус
`instrumentation: "detected"` подтверждает поддержанную лексическую форму привязки к каноническому
ABI 1 фасаду, проверенному по SHA, с соответствующим ID пакета. Это статическое свидетельство, а не
выполнение операции или полный семантический анализ. `not-detected` означает, что поддержанная форма
не найдена; оно не исключает иной пользовательской разметки. Неоднозначная привязка или ошибка
чтения даёт `unknown`.

Отдельный массив `observations` содержит логические ID, process/executor и число событий: `recorded`
получен из явного `extension_id`, `derived` — из префикса `operation_id`. Эти записи не
присваиваются физической копии пакета: один ID может встречаться в нескольких путях, а наблюдаемый
ID может не входить в выбранный инвентарь. В поле эксперимента
`coverage.json.observations[requestedId]` значение `observed` требует записанного `extension_id`;
иначе сохраняется `unknown`. Имя счётчика не доказывает наблюдение расширения.

Флаги `installed`/`instrumented`/`observed` с ключами `ts` и `lua` описывают языковых агентов и не
заменяют эти сведения о пакетах. Реестр также не доказывает установку, разметку или исполнение
пакета в конкретном курсе. Если старый coverage не содержит инвентаря, его состояние остаётся
`unknown`; нынешние исходники повторно не сканируются ради восстановления прошлого. Полные поля и
правила отсутствия пакета приведены в
[машинных форматах](general-use-formats.md#покрытие-выбранной-области).

## Качество и завершение

Сначала сопоставьте три независимых значения в `run.json`:

| Поле                             | Как читать                                   |
| -------------------------------- | -------------------------------------------- |
| `outcome.code`, `outcome.signal` | Фактическое завершение сборки                |
| `dataValid`                      | Пригодность собранных диагностических данных |
| `quality.coverageComplete`       | Полнота наблюдения в заявленном scope        |

Простой рендер сохраняет `quality.coverageComplete: false`. При этом `dataValid: true` означает, что
имеющиеся наблюдения пригодны в пределах их охвата. Успех Quarto не заменяет проверку данных, а
отсутствие события не доказывает отсутствия операции. `quality.errors`, `droppedEvents` и
`incompleteSpans` объясняют потери и незавершённые интервалы. Отсутствующее ожидаемое свидетельство
запуска агента или CPU-профиль — ошибка данных; неподдержанная либо не запрошенная возможность
учитывается отдельно.

`run.json.outcome` содержит `wallSeconds`, `cpuUserSeconds`, `cpuSystemSeconds` и `peakRssKiB`.
Недоступное CPU/RSS наблюдение равно `null`, а не нулю. `summary.json` содержит операции и счётчики;
пиковая память хранится в `run.json.outcome.peakRssKiB`.

Простой CLI возвращает нативный ненулевой код Quarto. Если сборка успешна, но данные или сохранение
отчёта невалидны, возвращается `4`; ошибка подготовки возвращает `2`. При прерывании сохраняется
фактический сигнал, завершается собственная группа дочерних процессов, затем сигнал передаётся
самому CLI. Для `SIGINT`/`SIGTERM` запись доступных данных выполняется по возможности; `SIGKILL` не
гарантирует финализацию. Возможность записать отчёт после отказа не превращает запуск в успех. Коды
расширенного эксперимента описаны [отдельно](experiments.md#коды-завершения).

Ошибка сканирования процессов сохраняет исходную причину и переводит наблюдение в управляемое
завершение собственного дерева процессов. Перед возвратом ошибки supervisor дожидается
подтверждённых собственных процессов и завершения чтения их потоков; известный исход нативной сборки
сохраняется отдельно. Ошибки прав и ввода-вывода не считаются исчезновением процесса и не дают права
сигналить чужим группам.

## Часы и счётчики

TypeScript использует монотонные часы процесса. Общая wall-шкала возможна только при сохранённой
калибровке; её неопределённость не ограничивает возможный системный дрейф между процессами. Lua
измеряет CPU-время процесса через `pandoc.system.cputime`, переводя пикосекунды в микросекунды до
арифметики; при отсутствии provider применяется `os.clock`. Lua CPU и TS wall читаются раздельно.
Некалиброванный wall тоже остаётся локальным для исполнителя.

Включающие интервалы могут перекрываться и вкладываться; их сумма не равна wall-времени сборки.
Недоступное self-time остаётся `null`. Счётчики вызовов, API-обходов, запусков фильтров и handlers
имеют разные значения. `full-document` объявляется в конкретной точке вызова; фрагмент Pandoc AST
сам по себе не становится полным документом. Дополнительного обхода для подсчёта узлов нет.
`summary`/`cpu` не оборачивают каждый обработчик узла ради подробной трассировки.

События `counter` — приращения, executor-summary — итог в той же области процесса, исполнителя и
имени счётчика. Если доступны оба источника, сумма записанных приращений сверяется с итогом.
Расхождение отражается в качестве данных; оба первичных свидетельства сохраняются отдельно и не
складываются в новое значение. Отсутствующий источник не заменяется нулём, а уже известные потери и
незавершённые записи сохраняют своё значение для оценки качества.

При расхождении `quality.errors` содержит сообщение `Counter ...: delta=..., total=...`, `dataValid`
становится `false`, а агрегаты получают `quality: "partial"`. Сообщение фиксирует противоречие, но
не приписывает ему неподтверждённую причину потери.

Пиковая память и CPU-итоги без временных выборок не образуют график. Точные поля и версии — в
[машинных форматах](general-use-formats.md).

## Выбранные инструменты и частые причины отказа

`QUARTO` выбирает исполняемый файл Quarto. Эффективные `QUARTO_DENO`, `QUARTO_PANDOC`,
`QUARTO_SHARE_PATH` и допустимые дополнительные опции сохраняют назначение при подготовке launcher.
Если выбранный runtime не предоставляет нужные preload/init/CPU-возможности, диагностический запуск
отказывает до сборки. Список возможностей доступен командой
`quarto-course-perf experiment capabilities --quarto /absolute/path/to/quarto`.

| Сообщение или ситуация                                 | Действие                                                                                                                    |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Конфликт окружения измерений                           | Уберите ранее включённые `COURSE_PERF_*`, `COURSE_BUILD_TRACE` или `QUARTO_*` profiler-настройки из окружения этого запуска |
| Конфликт `--cpu-prof`, `--prof` или `--inspect`        | Запустите диагностику без второго профилировщика в дополнительных Deno-опциях                                               |
| `perf-output` пересекается с результатом или ресурсами | Выберите отдельный внешний каталог                                                                                          |
| Нет доступного внешнего `staging`                      | Обеспечьте доступный для записи временный каталог вне проекта                                                               |
| Не удалось сохранить итог                              | Сохраните материалы по напечатанному пути `staging` и проверьте место/права итогового каталога                              |
| Нативная ошибка Quarto/Pandoc/исполнителя курса        | Читайте исходные stdout/stderr и фактический код; отчёт не подменяет причину отказа                                         |

Пользовательский `init.lua` в действительно выбранном Pandoc data-dir выполняется один раз при
подключении агента; исходные файлы сохраняются. В локальной проверке Quarto 1.11.6 обе формы
пользовательского `--data-dir` не выбирали этот каталог на нативном пути Quarto. Отдельная проверка
выбранного Pandoc подтвердила однократный init. Performance не обещает поведение, которого не даёт
сам нативный Quarto. Если используются Pandoc defaults, явный `--data-dir` должен идти после всех
`--defaults`: неоднозначный порядок диагностика отклоняет.
