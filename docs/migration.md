# Переход с Performance 1.0.0 на 2.0.0

Версия 2.0.0 добавляет установленную команду `quarto-course-perf render` и однократно переводит
активные конфигурации, source manifests и metadata запусков на схему v2. Тег 1.0.0 сохраняет свой
прежний интерфейс и не предоставляет новую команду. Новую версию устанавливайте по
[Arch-инструкции](arch-package.md).

## Текущие команды

| Задача                                                     | Интерфейс 2.0.0                                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------------------ |
| Измерить обычную сборку из каталога курса                  | `quarto-course-perf render [аргументы Quarto]`                           |
| Получить источники, закрепить варианты, выполнить сценарий | `quarto-course-perf experiment sources`, `freeze`, `run` с `--config` v2 |
| Сравнить варианты                                          | `quarto-course-perf experiment benchmark` с явной benchmark policy       |
| Построить или проверить отчёт живого эксперимента v2       | `quarto-course-perf experiment report` / `verify`                        |
| Прочитать исторический эксперимент без изменения источника | `experiment report` / `verify` с `--import-historical --output PATH`     |

При работе из checkout префикс установленной команды заменяется на `deno task perf` после
[подготовки зависимостей](development.md). Например, прежнее `deno task perf run ...` заменяется на
`deno task perf experiment run --config /absolute/perf.json ...`.

В конфигурации v2 явно задаются `projectSource`, `sources` и `replacements`. Сценарий задаёт
нативные `cwd` и `args`; прежние `project` и `courseProfile` не принимаются. Поле `outputPolicy` по
умолчанию равно `strict`, а сравнительное измерение требует явного `maxSlowdownRatio`.
[Новый пример эксперимента](experiments.md) показывает всю структуру. Не меняйте один номер версии в
старом JSON: заполните сведения из фактических источников и создайте новый workspace.

`run.json`, сводка одного запуска и сводная обёртка эксперимента имеют явную v2-структуру. ABI
фасадов остаётся `1`; сырые Event и executor-summary остаются `schema_version: 1`. Производный
`export.json` имеет собственную схему и не переименовывает первичные данные. Подробности — в
[контракте форматов](general-use-formats.md).

## Чтение сохранённого эксперимента

Обычные `sources`/`freeze`/`run` не принимают старую схему. Для исторического чтения явно задайте
исходный каталог и новый каталог результата:

```sh
quarto-course-perf experiment report --workspace /absolute/history-v1 --import-historical --output /absolute/history-v1-view
```

Та же операция доступна через `experiment verify`. `--import-historical` и `--output` обязательны
вместе и разрешены только для `report`/`verify`. При необходимости `--experiment` проверяет
ожидаемый идентификатор. Выход должен отсутствовать либо быть пустым каталогом, не пересекаться с
источником и не содержать его. Импорт не запускает Quarto, не получает новые refs и не
перезаписывает исходный эксперимент.

Адаптер сохраняет исходные metadata/отчёты в области `historical/` нового результата, копирует
потребляемые первичные материалы и строит производные отчёты. `import-provenance.json` и
`importProvenance` связывают результат с путями источника, SHA-256, версиями схем и версией адаптера
`experiment-history-v1`. Старые build status и известность сигнала сохраняются отдельно от
результата повторного анализа.

Неизвестные CPU/RSS остаются `null`, неподтверждённое Git-происхождение — `git: null`; версия
старого инструмента может быть `unknown`. Адаптер не выдумывает сведения для заполнения схемы.
Исторический вызов должен быть представим как исходная команда Quarto `render` с сохранёнными argv,
абсолютным cwd, сигналом, preparation и обязательными результатами. Иная команда, например старый
`quarto run`, или отсутствие обязательных native-фактов дают отказ до записи результата. Это не
утверждение о неуспехе исходной сборки: данных недостаточно для такого преобразования.

Предварительная проверка отклоняет символические ссылки и специальные файлы в потребляемых
материалах. Поздняя ошибка ввода-вывода при копировании может оставить частичный **новый** каталог
результата; исходник остаётся неизменным. Не используйте частичный результат как завершённый отчёт.
Для повторной попытки выберите новый свободный каталог.

Публичная функция [`importHistoricalExperiment`](../src/analysis/report.ts) предоставляет тот же
явный путь чтения. Активный `writeExperimentReport` принимает живые v2-данные; скрытого совместимого
слоя записи старой схемы нет.

## История и хранение измерений

Архив [первоначального плана](plan/README.md), его [контрольные суммы](plan/MANIFEST.md),
[отчёт Java-пилота](java-pilot-report.md) и прежние evidence сохраняются как история. Их числа,
пакеты, нормализации и ссылки относятся к указанным там исходникам и не подтверждают приёмку версии
2.0.0.

Новые простые запуски сохраняются в `.quarto/course-perf/runs/<run-id>`. Сбор текущего запуска идёт
через внешний staging, поэтому штатная очистка Quarto не уничтожает ещё не перенесённые материалы
этого запуска. Старая история внутри `.quarto` при native clean может исчезнуть; архивируйте нужные
запуски отдельно либо задайте внешний `--perf-output`. Пользовательский `.gitignore` не
переписывается, чужие удалённые scratch-данные Quarto не восстанавливаются.
