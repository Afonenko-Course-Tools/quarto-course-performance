# Передача Codex для последующей реализации

## Короткий стартовый запрос

> Реализуй Performance по этому пакету. Сначала прочитай README, требования, архитектуру, контракты, план и рецензию. В начале реализации получи актуальные Java и подключённые расширения из GitHub; текущие локальные копии не использовать как канонический источник. Разработай отдельный проект профилирования и согласованные PR расширений, проверь всё на Java. Разрешены существенные внутренние изменения и замена прежней телеметрии. В обычном режиме фасады возвращают исходные функции, внутренние агенты не загружаются. В первом этапе время Lua и TypeScript анализируется раздельно. Сохраняй пользовательские рабочие деревья. Не делай merge, Releases или публикацию курса. При новом существенном противоречии предъяви конкретные данные и варианты, продолжая независимую работу.

Этот запрос предназначен для будущей задачи. При чтении архива в текущем обсуждении не начинать реализацию автоматически.

## Первый исполняемый этап

- Обнаружить GitHub default branch tips и реально подключённые Java owner packages.
- Прочитать актуальные AGENTS/spec/README/package contracts; не принимать исторические release tasks за эту задачу.
- Создать изолированные рабочие checkout, immutable source manifest и runtime capabilities report.
- Проверить upstream build до инструментализации. Наличие локального успешного рендера из прошлого разговора не является evidence для нового source set.
- Зафиксировать очередность T-01—T-11 и конкретные пути, если fresh source layout изменился.

## Что считается передачей результата

Рабочий проект, самодостаточные owner packages с disabled-by-default разметкой, reviewable PR, source/package/runtime receipts, Java full student/full и выбранные диагностические сценарии, проверка семантики, off overhead status, coverage/quality, raw evidence и русское руководство.

Отдельно сообщить все FAIL/INCONCLUSIVE/unavailable значения. Не заявлять «полный trace», если source coverage partial; «ускорение», если нет ordinary benchmark; «overhead отсутствует», если сравнение не позволяет проверить заданный предел.

## Режим исполнения и автономность

План можно выполнить одним агентом последовательно. Делегацию, внешние сообщения и subagents не включать автоматически. Следовать текущим инструкциям среды и пользователя; они могут отличаться от перечисленных в старом архиве навыков.

Подготовка доказательств, локальные тесты и fixes внутри авторизованной реализации выполняются до любых необходимых финальных согласований. Публикационные действия за пределами заявленных PR не добавлять к задаче.
