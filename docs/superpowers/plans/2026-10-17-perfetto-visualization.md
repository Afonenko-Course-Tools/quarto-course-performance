# План визуализации измерений в Perfetto и Speedscope

> **Для исполнителя:** обязательный навык — `superpowers:subagent-driven-development`
> или `superpowers:executing-plans`. Выполнять задачи по порядку; состояние
> отмечать флажками. Этот документ фиксирует план, а не выполненную реализацию.

**Цель:** открывать измерения Course-Tools в Perfetto, а существующие V8
CPU-профили — в Speedscope, сохраняя первичные данные для машинного анализа.

**Архитектура:** расширить существующий экспорт Chrome Trace Event JSON и
связывающий его отчёт. Сборщики и ABI остаются общими для текстового отчёта,
машинного анализа и внешнего просмотрщика. UI и SDK просмотрщиков не входят
в исполняемую среду измеряемых курсов.

**Технологии:** TypeScript/Deno, существующие TS/Lua агенты, Chrome Trace Event
JSON, Perfetto UI/Trace Processor, V8 `.cpuprofile`, Speedscope.

**Спецификация:** [простой рендер и установка quarto-course-perf](../specs/2026-10-17-general-use-design.md),
раздел «Визуализация и машинный анализ». План охватывает только визуализацию и
выполняется как задача 10 [общего плана](2026-10-17-general-use-implementation.md).
Общий построитель материалов запуска даёт задача 5, контекст и проверенные
интервалы — задача 7, обновлённую Java-базу — задача 8 общего плана.
Экспортёр можно проверять синтетическими fixtures независимо от большого рендера;
его завершение не означает готовность CLI, Arch-пакета или всей версии 2.0.0.

## Общие ограничения

- Основной визуализатор — Perfetto, дополнительный — Speedscope.
- Первичные JSON/JSONL и их признаки качества сохраняются; новый общий runtime
  и SDK в распространяемых расширениях не создаются.
- Времена событий и `ts/dur` Chrome JSON — микросекунды; отображение UI — `ms`.
- `wall.trace.json` и `lua-cpu.trace.json` сохраняют разные шкалы.
- Логические дорожки и связи не означают реальные потоки ОС или измеренное
  время передачи управления. Неподтверждённые связи не рисуются.
- Счётчики без времени и `peak_rss_kib` остаются агрегатами. Периодический
  мониторинг CPU/памяти не добавляется.
- Базовая среда проекта — Quarto 1.11.5 / Deno 2.7.14. Дополнительная проверка
  системным Deno 2.9.7 фиксируется отдельно, если используется.
- Совместимость импорта проверяется на закреплённом Perfetto v58.2;
  версию фактически использованного Speedscope записать в результат проверки.
- Готовые файлы передаются механизму сохранения запуска в `.quarto/course-perf`
  или `--perf-output`; визуализатор не меняет очистку Quarto.
- Реальные проверки опираются на Java после отдельного перехода на новые
  согласованные версии расширений. Фиксируются итоговый Java SHA и hashes
  установленных пакетов; Cybersecurity отложен до его обновления.
- Экспорт сохраняет только реально записанный контекст. Отсутствующий документ
  остаётся неизвестным; owner, восстановленный из operation prefix, помечается
  `derived` и не выдаётся за записанный `attributes.extension_id`.
- Raw Event/executor-summary остаются v1; новые run/summary — v2.
  Производный экспорт сопровождает `export.json` v1, без изменения нативной
  оболочки Chrome Trace и без переписывания первичных данных.
- Новые README, инструкции и описания PR — по-русски. Архив `docs/plan` и
  исторические evidence не редактируются.

## Главные случаи для ревью

1. Перекрывающиеся async siblings и одинаковые границы интервалов — без ложного
   родительства; закрепляет задача 1.
2. UUID процессов и отсутствующая/нулевая калибровка — устойчивые дорожки и
   отдельное локальное время вместо ложной синхронизации; закрепляет задача 1.
3. Parent ID в другом процессе или другой шкале — только подтверждённые связи;
   закрепляет задача 2.
4. Повреждённые/незавершённые события и безвременные счётчики — без «успешных»
   интервалов или выдуманных графиков; закрепляют задачи 1 и 2.
5. Отсутствующий CPU-профиль, пробелы в пути и автономный запуск установленного
   приложения — рабочие ссылки только на реальные файлы; закрепляют задачи 3 и 4.

## Задача 1 — корректные дорожки и раздельные часы

**Файлы:** изменить `src/report/perfetto.ts`, `tests/analysis/quality.test.ts`;
создать `tests/report/perfetto.test.ts`.

**Интерфейсы:** вход — существующий `NormalizedRun` из
`src/analysis/normalize.ts`; подтверждённые пары даёт
`validatedIntervals(run:NormalizedRun)` задачи 7 общего плана.
Выход — расширенный результат `traces`:

```ts
interface TraceBundle {
  wall: ChromeTrace;
  luaCpu: ChromeTrace;
  localWall: { fileName: string; trace: ChromeTrace }[];
}
interface ChromeTrace {
  traceEvents: ChromeTraceEvent[];
  displayTimeUnit: "ms";
}
interface ChromeTraceEvent {
  ph: "M" | "X" | "s" | "f";
  name: string;
  pid: number;
  tid: number;
  ts?: number;
  dur?: number;
  id?: number;
  cat?: string;
  args: Record<string, unknown>;
}
function traces(
  run: NormalizedRun,
  processes?: ReadonlyArray<Record<string, unknown>>,
): TraceBundle;
```

`ChromeTraceEvent` — экспортируемый тип в том же файле для phases `M`, `X`,
`s`, `f`; его `pid/tid` — числа, а поля времени необязательны для metadata.
Задача 1 реализует `M/X`; задача 2 использует `s/f`. Аргумент `processes`
по умолчанию пустой, чтобы сохранить вызовы существующих проверок.

- [ ] Добавить fixtures и падающие тесты: два UUID дают разные числовые IDs;
  перестановка входных событий не меняет mapping; `args` сохраняет исходные
  `process_id`, `executor_id`, `span_id`, `parent_span_id`, `document_id`,
  `symbol_id`, `origin` и статус. Исходные `attributes` сохраняются вложенным
  `source_attributes`, не заменяя служебные поля качества экспортёра. Проверить
  `attributes.extension_id`, derived attribution и отсутствие документного
  контекста отдельно: exporter не придумывает document_id.
- [ ] Добавить падающие тесты несовместимого end: другой run/process/executor/
  operation/clock, дублированные begin/end и отрицательное время. В каждом таком
  fixture нет обычного `X` повреждённой пары; исходные записи остаются в raw,
  ошибка присутствует в quality. Совпадения одного span_id недостаточно.
- [ ] Добавить падающие тесты интервалов: A `[0,10]`, B `[5,15]` без родительства
  получают разные `tid`; истинно вложенный ребёнок сохраняет родителя; равные
  границы siblings не делают один вызов родителем другого.
- [ ] Добавить падающие тесты часов: `time_origin_ms: 0` — допустимая калибровка;
  отсутствие/NaN/Infinity не считается калибровкой. Такие wall-исполнители
  исключаются из общей wall-шкалы и получают `local-wall-001.trace.json` и далее,
  с детерминированным числовым индексом, без исходных IDs в имени файла.
- [ ] Закрепить assertions в тестах `async siblings use separate logical lanes`
  и `uncalibrated wall stays local`; `bundle` — результат `traces` соответствующего fixture:

  ```ts
  const slices = bundle.wall.traceEvents.filter(e => e.ph === "X");
  assert.notEqual(slices[0].tid, slices[1].tid); // fixture A/B без родительства
  assert.equal(bundle.localWall.length, 1); // fixture с одним некалиброванным executor
  ```
- [ ] Запустить `deno test -A tests/report/perfetto.test.ts`; подтвердить отказ
  новых assertions на старом экспортёре.
- [ ] Реализовать детерминированное сопоставление IDs и metadata названий.
  Использовать общие проверенные пары вместо независимого связывания по span_id.
  Внутри каждого исполнителя сортировать интервалы по началу, убыванию конца
  и ID; назначать первую логическую дорожку, на которой интервалы разделены
  во времени либо вложены согласно подтверждённому родительству. Иначе создавать
  следующую дорожку. Названия явно содержат «логическая дорожка».
- [ ] Сохранить uncertainty калибровки и локальность Lua CPU в атрибутах.
  `aborted` остаётся помеченным `aborted`; unmatched begin не превращается
  в завершённый `X`; отрицательная длительность не экспортируется как нормальная.
- [ ] Запустить `deno test -A tests/report/perfetto.test.ts tests/analysis/quality.test.ts`.
  Обновить старые assertions числа событий так, чтобы metadata не считались
  операциями: фильтровать `ph === "X"`. Проверки должны пройти.
- [ ] Зафиксировать изменения отдельным коммитом с русским описанием.

## Порядок исполнения и передача

Задачи 1–4 последовательны: общий экспорт, связи, отчёт, реальный импорт.
До задачи 3 готовы общий run builder и receipts/context общего плана; до реальной
Java-проверки завершён отдельный переход курса на согласованные новые расширения.
Для будущего исполнения рекомендуется работа в этой сессии с независимым
финальным ревью: задачи тесно связаны одним экспортёром, отдельные параллельные
реализации увеличат вероятность расхождения интерфейсов.

Исполнение входит в общий план. Добавление визуализации в план не означает,
что новый CLI, Arch-пакет или изменения экспортёра уже реализованы.
