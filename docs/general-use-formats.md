# Форматы общего измеряемого рендера

Контракт `run.json` задаёт `RunRecord` из [`src/report/types.ts`](../src/report/types.ts).
`RunSummary` описывает агрегаты одного запуска. Оба формата имеют обязательное числовое
`schema_version: 2`; `validateRunRecord` и `validateRunSummary` явно отклоняют другую
или отсутствующую версию. Версия установленной команды, версия metadata, ABI моста
и версия сырых событий независимы: выпуск CLI 2.0.0 сохраняет ABI 1 и raw Event v1.

Активные конфигурация, `SourceManifest`, `run.json` и сводки эксперимента используют v2. Обёртка
`summary.json` целого эксперимента содержит запуски; `RunSummary` остаётся сводкой одного запуска.
Старые данные читаются только через [явный исторический импорт](migration.md); изменение номера
схемы без подтверждённых исходных фактов не является миграцией.

## Запрос и завершение

`NativeRenderRequest` содержит обязательные `cwd`, `quarto`, `nativeArgv`, `mode`
и необязательный `outputParent`. `nativeArgv` хранит исходную последовательность
нативных аргументов после `render`, включая нативные разделители и значения параметров.
`cwd` и эффективный путь Quarto сохраняются отдельно от argv. `SimpleMode` принимает
только `off`, `summary`, `cpu`; `trace` относится к изолированному эксперименту. Общий `RunRecord.request` использует
`RunRequest`: те же поля запроса с `mode: Mode`, включая `trace`. Это позволяет
общему построителю сохранить фактический режим эксперимента; простой CLI по-прежнему
принимает только `SimpleMode`.
`outputParent`, если задан, является строкой, а не `null`.

Следующие поля `BuildOutcome` обязательны:

| Поле | Значение и единица |
| --- | --- |
| `code` | Фактический целочисленный код завершения дочерней сборки |
| `signal` | Фактический `Deno.Signal` либо `null`, если сигнал не зарегистрирован |
| `wallSeconds` | Неотрицательное конечное время измеряемой сборки, секунды |
| `cpuUserSeconds` | Пользовательское CPU-время, секунды; `null`, если недоступно |
| `cpuSystemSeconds` | Системное CPU-время, секунды; `null`, если недоступно |
| `peakRssKiB` | Пиковая резидентная память, KiB (1024 байта); `null`, если недоступна |

Дополнительно допускаются `escalated: boolean` и `stdioMode: "separate" | "pty-combined"`. Они
фиксируют усиление завершения группы процессов и выбранный способ сбора вывода, если эти сведения
присутствуют. Отсутствующее наблюдение CPU/RSS не заменяется нулём и не удаляется из JSON. Внешнее
wall-время не подменяет CPU-время или память. Код сборки и пригодность диагностических данных
оцениваются раздельно: неуспешная сборка может оставить корректные частичные свидетельства.

## Запись запуска

| Поле `RunRecord` | Обязательный смысл |
| --- | --- |
| `schema_version`, `runId` | Число `2` и непустой идентификатор запуска |
| `request`, `outcome` | Исходный запрос и фактическое завершение |
| `preparation` | Массив `PreparationReceipt`; пустой массив допустим |
| `dataValid` | Пригодность собранных данных, независимо от `outcome.code` |
| `quality` | `droppedEvents`, `incompleteSpans`, `coverageComplete`, `errors` |
| `versions` | Строки `tool` и `quarto`; обязательные `deno` и `pandoc` содержат строку либо `null` |
| `git` | `{root, head, dirty}` либо `null`, когда сведений Git нет |
| `collectionDirectory` | Фактический временный каталог сбора вне очищаемой `.quarto` |
| `outputDirectory` | Конечный каталог отдельного запуска |
| `artifacts` | Словарь реально сохранённых артефактов и путей относительно конечного каталога |

`quality` содержит неотрицательные целочисленные потери и число незавершённых интервалов, boolean
покрытия выбранного scope и массив сообщений об ошибках. Простой `render` сохраняет
`coverageComplete: false`. Пустой список ошибок не доказывает полноту покрытия. В `off` внутренние
операции не наблюдаются; пустой список агрегатов не является доказательством их отсутствия.

`git.head` — полный SHA коммита либо `null` для репозитория без коммитов;
`git.dirty` — boolean состояния пользовательских входов до создания текущих
результатов. При отсутствии репозитория используется `git: null`, а не
фиктивный чистый коммит. Локальный запуск с незакоммиченными входами не получает
воспроизводимость закреплённого чистого эксперимента.

Свидетельство подготовки сохраняет `kind`, `path`, `sourceHash`, `preparedHash` и
необязательный `sourceMapPath`. Пути receipt описывают фактическую подготовку;
ссылки на переносимые артефакты разрешаются от конечного каталога. После переноса
данных `collectionDirectory` остаётся свидетельством первоначального расположения,
а `outputDirectory` указывает итоговое. Эти значения не объединяются. Абсолютные
пути исходников пользователя не меняются общей заменой строк.

## Агрегаты и сырые данные

`RunSummary` обязательно содержит `schema_version`, `runId`, `dataValid`, `quality`,
массивы `operations` и `counters`. Счётчик хранит `processId`, `executorId`, `name`,
неотрицательное конечное `value`, `source` (`event` или `executor-summary`),
`semantics` (`delta` или `total`) и `quality` (`observed-exact` или `partial`).
Значение счётчика измеряется в единицах его имени, а не во времени.

Сырое событие `Event` v1 `counter` представляет приращение. Итог того же счётчика в сырой
executor-summary v1 представляет total в области того же процесса и исполнителя.
Это два свидетельства одного измерения: сумма дельт сверяется с итогом,
а не складывается с ним повторно. Различные исполнители не смешиваются без явной
агрегации; источник и качество каждого агрегата сохраняются.

Агрегат операции содержит `operationId`, `clockDomain`, `completed`, `errors`,
`inclusiveMicroseconds`, `selfMicroseconds`, `quality`. Часы бывают `monotonic_process` и
`process_cpu`; длительности заданы в микросекундах. Необязательные `extensionId` и
`extensionAttribution` сохраняют владельца и источник атрибуции (`recorded`, `derived` или
`unavailable`); неизвестный владелец может быть `null`. Счётчики завершений и ошибок — целые
неотрицательные числа. Если self-time не наблюдалось, `selfMicroseconds` равно `null`. Включающие
интервалы могут перекрываться; их сумма не является wall-временем сборки. Пиковая память, итоговые
CPU-значения и счётчики без timestamps остаются итогами, из них не создаются временные ряды.

## Чтение истории

Исторические metadata читаются отдельным адаптером `experiment report` / `experiment verify` с
обязательной парой `--import-historical --output PATH`. Новый результат создаётся вне исходного
эксперимента; raw JSON/JSONL, прежние отчёты и evidence не перезаписываются. Потребляемые ссылки и
специальные файлы, непредставимые команды и отсутствие обязательных native-фактов отклоняются.
Поздняя ошибка копирования может оставить частичный новый output.

`importProvenance` в импортированных metadata и общий `import-provenance.json` содержат версию
адаптера, пути и SHA-256 входов, исходные schemaVersion и build/data/signal status. Неизвестные
CPU/RSS сохраняются как `null`, неизвестные версия инструмента и доступность сигнала обозначаются
явно, а неподтверждённое Git-происхождение остаётся `git: null`. Полный маршрут и условия отказа
приведены в [миграции](migration.md).

Сырые `Event` и executor-summary сохраняют `schema_version: 1` без преобразования
в metadata v2. Производные экспорты имеют отдельные версии; их версия не
выводится из версии CLI или ABI.

Первоначальный аудит входов — вершины веток владельцев, неизменяемые теги, дескрипторы, установка
Java, исторические candidate-наложения и сохранённые хеши пользовательских деревьев закреплены в
[`general-use-inputs.json`](evidence/general-use-inputs.json). Этот исторический аудит входов не
заменяет результаты приёмки согласованных полных пакетов Java.
